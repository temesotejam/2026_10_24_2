# 新仕様の通常入力による狩猟ドライバー

`scripts/lib/modern-hunting.mjs` は録画ページと既存の操作ドライバーを受け取る補助です。ゲーム状態の書き換え、テスト用セーブの読み込み、敵の生成、時刻変更、テレポート、所持品の注入は行いません。ゲームの位置・生物・ブロック・所持品を読み取り、キーとマウス、既存の移動・採掘・UIを操作します。

```js
const h = createModernHunting(page, d, a, {
  ensureWeapon: async () => {
    // 実際の手持ち材料で予備の剣を作る処理。材料がない復活直後は何もしない。
  },
  recover: async (health) => {
    // 必要なら安全な場所へ戻り、実際の食料を補充して回復する処理。
    await a.recover(health);
  },
  maintain: async (state) => {
    // 敵が近くないouterloopで1回。実際のUIで不要品を収納し、食料を補充する。
  },
  onEvent: async (event) => recordEvent(event),
});
h.activate(); // setGuard対応版では、農業・回復などの内部guardも置き換える
await h.gather(
  { enderPearl: 13, string: 3, ammo: 32 },
  { timeoutMs: 2400000, arrowReserve: Infinity },
);
await h.collectRods(7, { timeoutMs: 600000, arrowReserve: 32 });
```

目標は「追加で何個得るか」ではなく、現在の所持品の総数です。確率ドロップがあるため、倒した回数で成功扱いにせず、実際に倒れた場所へ移動し、拾えた所持数を確認します。

`ammo` は実際の `arrow` 数と `feather` 数×4の合計です。矢32本を得るか、矢にできる羽根と矢を合計して32本分そろえます。これは羽根から自動で矢を増やす処理ではありません。後で本物の火打石と棒を使ったクラフトが必要です。別々に `feather: 8` と `arrow: 32` を指定すると両方を要求するので、OR条件には `ammo` を使います。

利用可能な個別メソッドは `collectPearls(13)`、`collectString(3)`、`collectFeathers(8)`、`collectArrows(32)`、`collectAmmo(32)`、`collectRods(7)` です。各メソッドの第2引数は `gather` と同じ設定です。

通常は近接を優先し、弓を使う場合も `arrowReserve` を超える分だけ使います。矢を集めるメソッドは既定で弓を使いません。生物の数が上限に達して目的の生物が出ない場合、村人を対象にせず、通常攻撃で他の生物を減らして出現枠を空けます。昼夜や出現・ドロップの抽選はそのまま進みます。

作業用の `h.guard` は、所持品や作業台の画面を閉じて戦い、元の作業位置と画面へ戻します。戻る途中の新しい敵でも歩行・掘削を中断します。体力12だから退避だけを続けることはなく、単独の敵には接近して攻撃します。低体力かつ複数の敵に近接されている場合は退避を試みます。武器がない復活直後には素手を使えますが、採掘用ツルハシを消耗させないため、予備の剣を用意することを推奨します。

`ensureWeapon` は有効な剣がないか、残り耐久が4未満のときに実行し、作成後に再観測して装備します。キャンプへの帰還やクラフトが必要な場合、呼び出し側でも敵に囲まれている状況を考慮してください。常用を終了する場合は `h.deactivate()` で既存guardへ戻せます。

この補助のファイル作成時点では、録画中のブラウザに接続して実演はしていません。通常録画での実行結果を観察して、操作側の調整を行うための初期実装です。

`maintain(state)` は狩猟の各outerloopで近くの危険がない場合に1回呼ばれます。呼び出し後は位置・体力・所持品を再観測します。検証用の所持品操作ではなく、実際のチェストUIや農業・クラフトを使う処理を呼び出し側で渡してください。必要なパール・羽根・糸・矢まで預けないよう、収納対象を限定します。

常用guardは敵がいない場合でも、操作中かつ所持品UIが閉じていれば食料18未満で実際のパンを食べ、元の持ち物へ戻します。体力16未満で食料18以上なら移動・攻撃を止めて1秒ずつ回復を待ちます。この待ち時間は通常の経路・採掘タイムアウトから除外され、敵が現れたら次の確認で応戦します。所持品UIが開いているときは、この自動食事・回復待ちを行いません。

エンドでは、ドラゴン戦の退避中に停止しないよう、このguardによる体力16までの自動休憩を行いません。自動食事は維持し、ドラゴンへの退避・回復は討伐ドライバー側で管理します。

目の位置が水ブロック内なら、敵の選択・食事・休憩より先に操作を解除してSpaceを1秒押し、水面へ泳ぎます。必要ならUIを閉じ、Spaceはfinallyで離します。戦闘ループ中も同じ呼吸優先処理を行います。これは通常の泳ぎ操作であり、位置や呼吸値は書き換えません。

## 家の角と高所の射撃への対処

戦闘中の移動は局所BFSで乾いた足場を探し、幅0.6・高さ1.8の身体全体と、移動中に角をかすめる範囲まで確認します。立ち位置がセル中心からずれている場合は、必要なら先に中心へ寄ってから曲がります。水路や飛び降りを最短距離だからといって横切る計画にはしません。

スケルトンや炎の敵が3ブロックより遠い、または高低差が1ブロックを超える場合、弓と使用可能な矢があれば先に射撃します。スケルトンが現に射撃できる位置にいる間は、戦闘の確認が止まる地形掘削を行いません。足場がなく弓も使えない場合は、遮蔽物の裏か射程外への退避を試みます。それもできなければ、射撃を無視して通常作業を続けず、チェックポイントを取れるようにエラーで停止します。

炎の敵は現実装では近接攻撃のみなので、弓が使えない場合でも、安全に近づくための通常の地形工事は許可します。ゲーム側の敵の強さや挙動を変更する処理ではありません。

`scripts/hunting-path.test.mjs` の5項目と、明示した独立セーブを使う `scripts/hunting-navigation-check.mjs` で確認します。後者の最終実行では、家角での体力12・弓なしの戦闘を体力10で、5ブロック高いスケルトン2体への戦闘を矢4本・体力17で終えました。高所への戦闘では地形工事は行っていません。初回は追跡停滞を検出して処理が停止したため、録画コントローラーのチェックポイントと併用します。これらのセーブは通常の録画とは別です。

## 通常射撃中の横移動

弓を発射した後の待ち時間には、照準に対して左右の通常A/D入力を交互に300ms入れます。動く前に幅0.6・高さ1.8の身体全体が通る1.8mの経路を検証し、水・溶岩・壁・足場の切れ目があれば反対側を試します。両側が危険なら横移動しません。各射撃では装備後の実際のプレイヤー位置と生きている対象を再観測して照準を合わせます。

独立した検証用セーブで、体力6から5ブロック高いスケルトン2体へ通常射撃し、矢4本・安全確認後の横移動4回で討伐し、体力3で生存しました。地形工事は行っていません。`scripts/hunting-navigation-check.mjs --low-health` で再現し、この検証用セーブを通常の録画には使いません。
